# 答えの形

深さは3段階。既定は2。どの深さでも、節の名前と順番は変えない（毎回同じ場所に同じものがあると、読み手は探さずに済む）。

## 深さ2（既定）

```markdown
**一言**：<事実で1〜2文。誰が・いつ・何を・いくつ、を入れる>

**要点**
- <4〜5点。各1〜2文。定義、仕組み、由来、違い、理由のうち、質問に効くもの>

**例**：<1つ。概念の質問なら具体的な場面、事実の質問なら数値や日付の小さな表でもよい>

**注意**：<誤解されやすい点や限界を1〜2点。なければ節ごと省く>

**出典**
1. ○ <タイトル> — <発行者>（<日付>）<URL>
2. △ ...

**次に聞けること**：<質問の候補を2〜3個、「／」で区切る>
```

- 一言：質問への直接の答え。「〜だから」だけで終えず、根拠になる事実（人、年、数、名前）を入れる
- 要点：一行に一つのことだけを書く。一言の言い換えを繰り返さない
- 出典の記号：`references/credibility.md` の基準で付ける
- 全体で、日本語でおよそ400〜700字に収める

## 深さ1（「一言で」「ざっくり」）

一言と出典だけ。

## 深さ3（「詳しく」「ちゃんと知りたい」）

深さ2に、次の2節を要点の後に足す。出典は5件まで、検索の上限は5回にする。

```markdown
**背景**：<成り立ちや歴史を3〜5文>

**比較**
| 観点 | A | B |
| --- | --- | --- |
```

## 例（深さ2）

質問：「HTTPとHTTPSの違いってなんだっけ」

```markdown
**一言**：HTTPS は、HTTP の通信を TLS（もとは SSL）で暗号化したもので、1994年に Netscape が自社のブラウザー Netscape Navigator のために作った。URL は `https://` で始まり、既定のポートは HTTP の80に対して443を使う [2][3]。

**要点**
- HTTP はメッセージを平文のまま送受信するが、HTTPS は SSL/TLS や QUIC を使って、サーバーの認証、通信内容の暗号化、改ざんの検出を行う [1]
- これにより、なりすまし、中間者攻撃、盗聴を防げる [1]
- 仕様は2000年5月の RFC 2818 で最初に標準化され、今は HTTP 本体の仕様である RFC 9110 に取り込まれている [1][3]
- HTTP/3 では、下の層の QUIC が暗号化を担う [1]

**例**：公衆無線LANで `http://` のサイトにログインすると、同じネットワークにいる第三者に、送ったパスワードを読まれるおそれがある。`https://` なら通信の中身は暗号化されるので、途中で読まれない。

**注意**：HTTPS が守るのは、通信の相手が本物であることと、途中で読まれたり書き換えられたりしないことまでで、サイトの中身が安全かどうかは保証しない。なお、Google は2018年7月以降、Chrome で HTTP のサイトに「Not Secure」（保護されていない）と表示している [2]

**出典**
1. ○ HTTPS — Wikipedia（2026-08-29 更新）https://ja.wikipedia.org/wiki/HTTPS
2. ○ HTTPS — Wikipedia（英語版、2026-11-03 更新）https://en.wikipedia.org/wiki/HTTPS
3. ○ RFC 2818: HTTP Over TLS — RFC Editor（2000-05）https://www.rfc-editor.org/rfc/rfc2818

**次に聞けること**：TLS のハンドシェイクの流れ／証明書の種類（DV・OV・EV）の違い／HTTP/3 と QUIC の関係
```
