# quick-research

軽く聞いた質問に、毎回同じ形と深さで、確かめた事実を返す。読み手が求めているのは「すぐ読めて、どこまで信じてよいかがわかる答え」であり、網羅ではない。答えが長い散文になると、結論を探すのに読み手の負担がかかるため、形を固定する。

`<SKILL>` は、この SKILL.md があるディレクトリの絶対パス。スクリプトは `uv run` で動かす（依存は初回に自動で入る）。`uv` がなければ、利用者に `brew install uv` を頼む。

## 流れ

1. 質問を読む（種類、深さ、検索語）
2. 検索して、読むページを選ぶ
3. `gather.py` で本文を取り、関係する段落だけを読む
4. 答えを書く
5. `verify.py` で照合し、外れたところだけ直す
6. 返す

作業用のファイルは、スクラッチパッド（なければ一時フォルダー）に `quick-research-<短い名前>/` を作って置く。

## 1. 質問を読む

- **種類**を決める
  - 概念：意味、仕組み、由来、理由、違い（例：「なんでデザインパターンを用意するのか」）。答えの骨組みは知識で書けるが、事実（人名、年、数）は出典で確かめる
  - 事実：版、日付、数値、仕様、今の状態（例：「Python の最新版は」）。知識は古い可能性があるので、必ず検索で確かめ、出典の日付を見る
- **深さ**を決める。既定は2。「一言で」「ざっくり」は1、「詳しく」「ちゃんと知りたい」は3（形は `references/answer-format.md`）
- **解釈**：意味が二通り以上に取れて、答えが大きく変わるときだけ聞き返す。それ以外は、もっともらしい解釈で進め、答えの最後に「〇〇の意味で答えました」と一行書く
- **検索語**を2〜3個作る。分野の一次情報が英語に多いなら（ソフトウェア、学術）、英語の検索語を1つ入れる

## 2. 検索して、読むページを選ぶ

上限は **検索3回、`gather.py` に渡すページ4件まで**。

- 検索結果から、一次情報を優先して2〜4件を選ぶ。一次情報とは、話題の当事者が出したもの（公式の文書、仕様、原典の書籍や論文、作者の記事）である。まとめサイトや、出典を示さない解説は、ほかに無いときだけ使う
- 概念の質問でも、最低1件は取る。知識で書いた事実を照合する相手が要るため
- 上限を超えないと答えられないと分かったら、そこで止めて、分かったことを答えの形で返し、「deep-research で調べ直しますか」と聞く。上限を黙って超えない

## 3. 本文を取る

```bash
uv run <SKILL>/scripts/gather.py --out <作業フォルダー> \
  --query "検索語1" --query "検索語2" URL1 URL2 ...
```

出典ごとに、日付、書き手、参考文献の有無と、質問に関係する段落（既定で上位4つ）だけを出す。ページを WebFetch で丸ごと読まない（トークンを使いすぎるため）。抜粋で足りないときだけ、`<作業フォルダー>/sources/<番号>.txt` を grep して前後を読む。

`取得できなかった` と出たページ（ログインが要る、JavaScript で描くページなど）は、WebFetch で読んでよい。その内容は照合に使えないので、答えでは知識と同じ扱い（照合されていない）とする。

## 4. 答えを書く

`references/answer-format.md` の形で `<作業フォルダー>/answer.md` に書く。次を守る。

- **一言は事実で書く**：誰が、いつ、何を、いくつ、を入れる。「〜だから」「〜のため」のような抽象的な言い換えだけで終えない
- 要点の各行は、抜粋か知識のどちらかに基づく一つの事実か説明にする。推測は「〜と考えられる」と書き、事実と分ける
- 出典が食い違うときは、両方を書き、どちらが新しいか、どちらが一次情報かを添える
- 出典の番号は `gather.py` の番号（`[1]`）にそろえる

## 5. 照合する

```bash
uv run <SKILL>/scripts/verify.py --answer <作業フォルダー>/answer.md --work <作業フォルダー>
```

出力は3つ。読み方と直し方は `references/credibility.md` にある。

- **確かめられる語**：年、数値、書名、英字の固有名詞、カタカナの人名が、どの出典の本文にあるか。`未確認` の語は、(a) 抜粋や本文の grep で裏付けが見つかれば出典を足す、(b) 見つからなければ「（未確認）」を付けるか、その語を削る
- **一言・要点の支え**：各行を支える出典の数（○ 2つ以上、△ 1つ、× なし）。文字の重なりによる目安なので、× の行は、説明の文（知識による説明）なら残してよい。事実を述べた行が × なら、(a) か (b) で直す
- **出典の手がかり**：日付、書き手、参考文献、支えた行の数。これを見て、出典の一覧に記号を付ける

直すのは1回だけ。直した後にもう一度 `verify.py` を実行し、残った未確認の語は、答えの中で「（未確認）」と分かるようにして返す。

## 6. 返す

`answer.md` の中身を、そのまま会話に出す（ファイルは渡さない）。作業の経過（何回検索したか、照合の結果の表）は書かない。読み手が見たいのは答えだけである。
